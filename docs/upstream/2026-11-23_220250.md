Bluetooth: Classic: SCO: Avoid holding command buffers across HCI hooks

Prepare SCO setup and accept parameters on the stack and invoke the
HCI hooks before allocating the command buffer. The NXP hooks send
vendor-specific commands and would otherwise wait indefinitely when
the caller holds the last buffer in the command pool.

Copy the parameters after the hooks return so their changes are
preserved. Document the callback parameter lifetime.

Validated with the single-buffer SCO tests on qemu_x86/atom.
